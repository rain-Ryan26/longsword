# 建筑选址自动让位

## Context

当前建筑选址规则（[core.js L67](file:///e:\D_C_tryings1\longsword/src/core.js#L67)）：建筑占地格内只要有存活单位就拒绝建造（"请先移开占地内的部队"），玩家必须先手动把部队移开才能选址，操作繁琐。

目标：区域内只有**我方可移动单位**时允许下达建造命令；下达后这些单位自己走到建筑周边最近的空地，全部离开后建筑才开始施工。敌方单位占地仍拒绝（无法命令敌人离开）。

已与用户确认的设计决策：
- 敌方单位占地 → 仍然拒绝建造。
- 兵种数据加 `movable` 标记（当前 shield/archer/wilddog 均标记为可移动），未来不可移动单位占地时拒绝。
- 资源（食物/矿产）仍在下达命令时扣除（"选址后扣费并占地"），与现状一致。

## 关键设计

新建筑进入两种叠加状态：`awaitingEviction`（等待区域清空）+ `constructionPending=true`（保持为 true 可复用现有全部门控：不产资源、不开火、不训练、不参与视野、不可被采矿场判定，无需改动这些分支）。

让位单位打上 `u.leavingId = 建筑id`，使其寻路/移动时忽略该建筑的占地（"幽灵"占地），从而能从占地格内部走出来；建筑此时尚未真正施工。

## 改动清单

### 1. src/data.js
- shield / archer / wilddog 各加 `movable:true`。

### 2. src/core.js

**placement(type, point)**（L52-68）
- 替换 L67 的单位检查：区域内若有敌方单位（`u.team!==0`）或不可移动单位（`STATS[u.type].movable===false`）→ 返回 `'请先移开占地内的部队'`。
- 成功返回值追加 `evict: 区域内存在我方可移动单位`（供 UI 提示）。

**新增辅助方法**
- `evictTarget(b, u, list=this.buildings)`：目标点 = 从建筑中心穿过单位方向外推 `r+2`（`r=STATS[b.type].halfSize||2`），再 `nearestFree(map, list, ...)` 吸附到占地外最近可行走格；单位与中心重合时方向回退为 +x（`d>1e-6?dx/d:1`）。**注意 list 必须包含该建筑**（build 阶段建筑未加入 this.buildings，传 `[...this.buildings, site]`），保证目标点不会落进占地内。
- `stillLeaving(u)`：`u.leavingId` 对应存活建筑的占地格内是否仍包含 `floor(u)`。

**build(ids, type, point)**（L70-82）
- placement 通过、资源充足后，计算占地内所有我方可移动单位 `evictees`（不限选中 ids——占地内所有我方单位都必须让位）。
- 无 evictees → 走原流程（立即 dispatchBuilders 施工）。
- 有 evictees → 为每个单位算目标点（用 `[...this.buildings,site]`）；任一找不到目标点则返回 `'请先移开占地内的部队'`（不扣费）；否则扣费 → `addBuilding` 并置 `b.awaitingEviction=true; b.constructionPending=true; b.activeBuilders=0; b.builderIds=ids` → 对每个 evictee 置 `allowMountains=true`（避免占地内山地格清路径）、`leavingId=b.id`、`buildingId=null`、`holdFire=false`（holdFire 会跳过一切移动，必须清除）、`order='move'`、`goal=target`、`path=pathFor(u,target)`、`repath=1.5`，清空 waypoints/targetId。此时不派施工人员，等清场后再派。

**pathFor(u, end)**（L21-25）与 **move(u, amount)**（L216-220）
- 当 `u.leavingId!=null` 时，把传给 `findPath` / `walkable` 的 buildings 过滤掉 `id===u.leavingId` 的建筑，让让位单位能走出幽灵占地。

**step(dt)**（L130-214）
- 建筑循环开头（constructionPending 分支之前）插入 awaitingEviction 分支：
  - 计算占地格内所有存活单位 `inside`。
  - 若有：对每个单位 `u.leavingId=b.id`（新走进来的我方单位一并清场）；若 `u.order!=='move'||!u.path.length` 则用 `evictTarget(b,u)` 重新下达让位移动（兜底 0.8 格到达判定导致的"停在占地内"卡死），`continue`（本步不施工、不生产）。
  - 若清空（无任何单位）：`b.awaitingEviction=false`；清所有 `leavingId===b.id` 的单位的 leavingId 并 `allowMountains=false`；`builderAssignments(b.builderIds,b)` + `dispatchBuilders`（可能为空，空则维持现有"等待施工人员到场 · 右键补派"的 HUD 提示）；`continue`。
- 单位循环 L197 的到达判定加守卫：`distance(u,u.goal)<.8 && !this.stillLeaving(u)` 才算到达，否则继续沿路走（配合上面兜底，保证让位单位最终走出占地格）。

**releaseBuilders(b)**
- 额外清理 `leavingId===b.id` 的单位（置 leavingId=null、allowMountains=false）。建筑被摧毁/拆除（demolish 与 step 的 hp<=0 分支都走 releaseBuilders）时清干净。

## 边界处理（已排查）
- **卡死防护**：让位单位到达判定叠加 `stillLeaving` 守卫 + 建筑循环每步兜底重发让位指令，保证最终走出占地格（0.8 格判定区间 + 目标点外推 r+2 的组合不会振荡）。
- **山地**：让位单位强制 `allowMountains=true`，避免占地内山地格清空路径；离开后非施工人员恢复 `allowMountains=false`。
- **holdFire**：让位单位必须清 `holdFire=false`，否则 L171 会跳过一切移动。
- **资源**：目标点找不到（单位被围死）时在扣费前拒绝；扣费时点与现状一致。
- **让位期间新单位走入占地**：建筑循环会把区域内任意我方存活单位纳入让位（自动补发）。
- **敌方走进占地**：寻路会绕开建筑（enemy 无 leavingId），实际不会发生；清场判定按"区域无任何单位"处理兜底。
- **视野/产能/开火/训练**：因保持 `constructionPending=true`，全部自动沿用现有门控，无需额外改动。
