# 性能与窗口同步

本目录记录代码实现和性能方案；`docs/design` 保留玩法、规则和 GUI 等游戏设计。实现验证记录放在 `docs/实现`。

## 渲染

- 渲染上限 120 FPS；逻辑保持固定 50 毫秒步长，不改变游戏规则。
- 地形按地图对象缓存；迷雾按地图、阵营视角、视野版本缓存。视野数组原地修改时仍须递增版本。
- 小地图缓存地形与迷雾背景，战局版本变化时更新单位层；镜头框单独绘制。
- 画布尺寸使用 ResizeObserver 标记变化，像素比变化也触发更新；不逐帧读取布局。
- 战局、视野、镜头、选择、拖框或尺寸变化时重绘；指令标记动画持续到期并补画清除。暂停后的静止画面不重复绘制。
- 屏幕外实体跳过绘制，保留血条和标签余量；选中单位的路径可能穿过屏幕，不能随单位一起裁掉。
- 重开、地图替换和视角切换必须使相关缓存失效。

## 观察窗口

- 观察页每秒发送身份与已接收地图、视野版本的心跳；主窗口仅向最近 5 秒内活跃的观察页发送快照，退出时主动注销，失联时超时清理。
- 首次连接、重开或接收方缺少当前地图时附地图；视野版本变化时附双方视野及探索数据。动态状态维持最多约 10 次/秒，暂停期间也维持连接反馈。
- 每个接收方独立确认版本；重新连接可恢复完整状态。主窗口以运行实例和重开序号区分地图版本，避免主窗口重载后误用旧地图。
- 接收状态时保留未随消息发送的地图与视野；完整数据未就绪前请求恢复，不展示混合战局。
- 不引入逐单位增量协议、Worker 或新依赖。

## 模拟与代码职责（本轮实施约定）

- 执行顺序与证据见 [性能优化记录](../stage/性能优化.md)。保留固定 50 毫秒逻辑步长及原阶段先后顺序。
- 地面视野用访问戳记复用距离缓冲区，不跨次缓存地形搜索结果；地图或地形改变后立即按当前数据计算。
- 输入模式统一切换，HUD 从状态读取；训练规则和升级映射由核心与 HUD 共用，玩家/AI 的既有科技差异保留。
- 空间查询及建筑占地缓存必须反映移动、建造、拆除和让位；重开不得复用旧战局状态。

## 验证

- 缓存命中、视角切换、视野更新、重开、尺寸和像素比变化；屏幕外路径、标记到期和暂停交互。
- 无观察页不广播、多个观察页首次连接及确认、超时清理、丢失地图后的恢复。
- 运行既有规则测试；绘制调用计数只证明减少重复工作，实际 CPU/GPU 与帧时间收益需浏览器测量。
