# 3D 渲染阶段方案

状态：待确认，尚未授权实施或安装依赖。

## 目标与判断

- 保留现有二维网格规则，以 3D 表现替换战场画面；逻辑坐标 `(x, y)` 映射为 3D 的 `(x, height, z=y)`。
- 目标规模至少 200 个单位，当前进攻关实际约 277 个单位、18 座建筑、128 × 88 地图。
- 120 FPS 每帧预算为 8.33 ms。低模单位的三角形数量不是主要风险，draw call、主线程逻辑、像素分辨率、阴影、透明效果和状态上传更关键。
- 当前本机 Node 基准中，进攻关 200 个逻辑步约 735 ms，平均每个 50 ms 逻辑步约 3.68 ms；一次全军攻击命令约 14.26 ms。该结果不含浏览器和 GPU 渲染，只说明 120 FPS 可能存在偶发逻辑掉帧，不能据此承诺稳定帧率。

## 当前推荐技术

- 使用 **Babylon.js** 负责战场 3D 渲染、镜头、拾取、实例化和性能统计。
- 首先以 **WebGL2** 为兼容基线；WebGPU 仅作为同场景实测的可选后端，不依赖 WebGPU 才能达标。
- 保留现有原生 JavaScript 与 DOM HUD；不为本轮 3D 改造额外引入 React。
- 暂不引入物理引擎、骨骼动画、PBR 材质或复杂后处理。若正式工程化需要打包和类型检查，再单独确认 Vite/TypeScript 迁移。
- Three.js 仍是可行备选，但它更偏渲染库；对当前包含 RTS 镜头、拾取、迷雾和后续模型加载的项目，Babylon.js 更适合作为首个验证方案。

## 单位表现

- 第一版使用程序化低模：胶囊体、低分段球体、Box 和细圆柱组成身体与武器，不依赖 Blender 资产。
- 弩兵可由胶囊身体、弩身长方体、两段弩臂、弦和小握把组成；整体朝移动或攻击方向旋转。
- 同一兵种的零件先合并为一份几何体，再按兵种和阵营实例化；避免每个单位的每个零件都成为独立 Mesh。
- 第一版可使用普通 instances；如 CPU 场景树经实测成为瓶颈，再换 thin instances，并维护单位 ID 与 instance index 的映射。
- 只做整体上下起伏、转向和攻击后坐等简单动画，不使用骨骼。远距离可隐藏武器细节或改用兵种图标。
- 选择圈和假阴影使用实例化圆片；不开逐单位实时阴影。

## 地形与玩法边界

- 整张地图生成一个共享顶点的低模地形网格，地形类型用顶点色或小纹理表现。
- 第一阶段高度仅作视觉表现：平地为 0，森林轻微起伏，山地平缓抬升；单位渲染高度从高度场采样。
- 现有寻路、碰撞、移动速度、攻击和视野仍读取二维网格，不因视觉高度改变。
- 山地不能画成不可跨越的峭壁，因为现行规则允许单位减速通过。
- 如果以后让高度影响通行、视野、射程或弹道，应先作为玩法规则单独设计，再修改核心逻辑。

## 镜头、输入与界面

- 使用受约束的 RTS 透视镜头：围绕地面目标点平移、旋转和缩放，限制俯角，禁止进入地下或任意翻转。
- 点击地面改为射线与地形求交；点击单位通过拾取结果映射到逻辑单位 ID。
- 框选和双击同类选择时，将候选单位的 3D 位置投影到屏幕，再复用屏幕矩形判断。
- 为输入层保留稳定的 `screenToGround`、`worldToScreen`、镜头移动和缩放接口，避免 Babylon 对象进入游戏规则层。
- 小地图继续使用 Canvas2D。HUD、提示、血条和文字优先保留 DOM/CSS 或透明 Canvas2D overlay，不全部改成 3D GUI。

## 状态同步与战争迷雾

- 现有逻辑保持 50 ms 固定步长；渲染层保存前后两个逻辑状态，在 120 Hz 帧循环中插值位置和朝向，避免单位以 20 Hz 跳动。
- 迷雾使用低分辨率纹理，只在 `visionVersion` 变化时更新；地形材质区分当前可见、已探索和未探索区域。
- 敌方实体是否进入实例批次仍由 CPU 按当前阵营视野判断，避免在迷雾中泄漏实时位置。
- 观察窗口仍传输项目自己的战局快照，不传输或序列化 Babylon scene。

## 首版性能约束

- 单位和植被批量实例化，控制 draw call；禁止按单位创建材质。
- 使用简单不透明材质和少量固定光源；不启用动态实时阴影、SSAO、景深、泛光或动态反射。
- 限制渲染像素比，必要时提供 1.0 / 0.85 / 0.7 的分辨率比例或自动降档。
- 更新实例矩阵时复用 typed array、矩阵和临时对象，不逐帧制造大量垃圾。
- 分开记录 CPU frame time、GPU frame time、draw calls、平均 FPS 和低分位帧时间，不能只看平均 FPS。

## 验证顺序

1. 增加可切换的独立 3D renderer，只显示现有进攻关地形、277 个静态单位和建筑，保留 Canvas2D renderer 作为对照。
2. 接入单位实例矩阵、朝向和 20 Hz 到显示刷新率的状态插值。
3. 接入镜头、地面拾取、点选、双击和框选。
4. 接入迷雾、选择圈、假阴影、血条、路径、弹道和建造预览。
5. 使用同一战局快照对比 Canvas2D、Babylon WebGL2 和可用时的 Babylon WebGPU。
6. 分别测试 200、500、1000 单位，以及 1080p、1440p 和高 DPI；覆盖全军下令、视野刷新、快速移动镜头和大量弹道。

## 建议验收线

- 在指定目标电脑和浏览器的 1080p 场景中，200～300 单位普通战斗以 120 FPS 为目标，主要帧时间不超过 8.33 ms。
- 500 单位至少稳定 60 FPS；记录低分位帧时间和瞬时卡顿，不以短时平均值代替结论。
- 若不达标，优先降低渲染分辨率、阴影、透明与特效成本，再调查逻辑尖峰；不先削减目标单位数量。
- 在完成真实浏览器原型和性能记录前，只能表述为“120 FPS 有希望”，不能宣称已验证。
