# 性能优化与重构

## 审阅记录（2026-09-12）

当前主要问题是职责混杂、规则重复、长函数密集。`src` 审阅时约 1470 行，采用逐块重构，不更换技术栈、不新增依赖、不改变玩法。

- `core.js / step` 同时处理施工、经济、治疗、训练、AI、视野、战斗、弹道和胜负。
- `app.js` 用多个变量维护攻击、建造、科技、集结点模式，输入与 HUD 耦合。
- 训练条件、升级映射、资源点覆盖、关卡介绍存在重复；进攻旧版实际 50 盾/50 弓、敌方 40 盾/40 弓，而介绍使用另一版数值。
- 视野对每个地面实体分配整图距离数组并搜索；分离遍历全部单位对，索敌反复扫描排序，寻路逐格扫描建筑。
- 渲染和同步已有缓存及专项测试，暂不大改。

审阅时三个关卡分别运行 200 步、每步 0.05 秒，未额外下达命令：

| 关卡 | Node 模拟总耗时 | 视野更新耗时 |
| --- | ---: | ---: |
| 演示 | 776 ms | 618 ms（80%） |
| 进攻 | 1455 ms | 1006 ms（69%） |
| 均衡 | 226 ms | 191 ms（84%） |

这是一次开局短时粗测，不代表浏览器帧率或密集战斗表现。视野是优先验证的性能热点。

此前核心测试 61 通过、2 失败，均衡 9 通过、渲染/同步 7 通过。核心失败来自测试依赖演示关旧兵力和旧人口上限。开始实施时检测到用户已有配置与测试修改，保留这些修改；以下记录以重新验证为准。

## 实施与验证

- 测试基线：新增 `tests/fixtures.js`，核心 63 项通过，保留用户已有演示关机械和 200 人口配置。
- 视野：新增 `src/vision.js`，使用访问戳记复用整图缓冲、跳过过期堆项，同次更新按阵营/起点/预算去重。参考算法覆盖混合地形、边缘、修改地形、换图及同格不同预算。
- 视野阶段对照：当前修改前副本与新实现各运行 200 步，三个关卡最终快照完全一致；演示 825→294 ms、进攻 1464→712 ms、均衡 259→85 ms。这是一次 Node 对照，不是浏览器帧率承诺。
- 交互：新增 `src/interaction.js` 和 `src/hud.js`，模式切换统一清理选择/预览，HUD 只读状态。浏览器已确认暂停、F2、B/Q 建造、放置切换 A 攻击后关闭建造面板；其他取消和重开路径将在最终验证中补齐。
- 拆分更新：`src/core.js` 的 `step` 拆出科技/建筑/训练/AI/单位/塔/弹道等子方法，保持阶段顺序与施工剩余生产时间；核心 63 项测试通过。
- 统一规则：新增 `src/rules.js` 与 `src/levels.js` 共用训练校验、科技映射、资源与关卡兵力；`refactor.test.js` 与核心测试通过，玩家/AI 差异保留。
- 查询与寻路：`step` 单次构建 `entityById` 供单位/塔/弹道取目标，`acquireTarget` 单次选最优并保持稳定序；`src/separation.js` 按格网分桶做局部单位挤动；`src/pathfinding.js` 的 `createWalkability` 以签名缓存建筑占地。`refactor.test.js` 覆盖建筑占地缓存、空间分桶一致性、索敌稳定序与弹道失效，全部通过。
